# Usage

Runnable examples of `IAppInfo` in different situations.

## Read the product identity

```csharp
IAppInfo info = new IAppInfo.Factory().Create(typeof(Program).Assembly);
Console.WriteLine($"{info.Name} {info.Version}");
```

The version comes from the assembly, so a published build reports the release version it was built with.

## Run the server with a config file

`config.json` (or the path passed as the first argument):

```json
{
  "port": 52679,
  "key": "change-me",
  "dataFolder": "/home/you/.local/share/AutoRemote",
  "defaultFolder": "/home/you",
  "claudeCommand": "claude",
  "claudeArguments": [],
  "codexCommand": "codex",
  "codexArguments": [],
  "dotnetCommand": "dotnet"
}
```

```
Markwardt.AutoRemote.Server config.json
```

Only `key` is required; the other values shown are the defaults (`defaultFolder` defaults to the server user's home folder, and the example shows what that is on one machine). `port` (default 52679) is the one port every client connects to (secure WebSocket) and must be 1 to 65535, and the key non-empty, otherwise the server prints the problem and exits with code 1. `dataFolder` is where the server stores workspaces, the groups they are filed in (groups can contain groups) and conversations (a `history` folder); it is created when missing and defaults to the `AutoRemote` folder of the server user's application data. `defaultFolder` must be an existing folder: it is where a client starts when browsing for a new workspace's folder. `claudeCommand` and `codexCommand` must resolve to the Claude Code and Codex executables on the server's machine (only for the services in use), and `claudeArguments` and `codexArguments` are added to every run of that service. `dotnetCommand` must resolve to the .NET SDK on the server's machine when scripts are run. Prompts always run without permission prompts (`--dangerously-skip-permissions` for Claude Code, `--dangerously-bypass-approvals-and-sandbox` for Codex), since they run unattended and cannot ask.

All connections are secure WebSockets (`wss`). The server presents the PFX named by `certificateFile` (with `certificatePassword` if it has one); without it, the server creates a self-signed certificate as `certificate.pfx` in the data folder on first start and prints its SHA-256 fingerprint on every start. A client connects to `port` and sends its access key as a JSON line. The server replies with a JSON line saying whether it was accepted, and keeps the connection open or closes it. Keys are compared in constant time, the line is limited to 1024 bytes, and a client has 5 seconds to send it.

The server writes a timestamped line to its console for each connection: when it arrives, when TLS is established, whether the client was accepted or why it was refused (wrong key, no handshake line within 5 seconds, a connection that closed or sent something else, no WebSocket upgrade), when it disconnects and how long it was connected, and any error that ended it. Keys are never logged. The clients log the same stages from their side (connecting, WebSocket and TLS established with the certificate fingerprint, accepted, or the stage that failed and why, and a lost connection) to the console: the terminal on desktop, logcat on Android (which `Scripts/Support/MobileClient.cs` streams) and the browser console on the web.

## Talk to the server from code

```csharp
IServerConnection.IFactory factory = new IServerConnection.Factory(new IMessageChannel.Factory());
await using IServerConnection connection = await factory.Connect(new ConnectionSettings { Host = "192.168.1.20", Port = 52679, AccessKey = "change-me" }, cancellation);

FolderListing start = await connection.ListFolders(null, cancellation);
FolderListing project = await connection.CreateFolder(start.Path, "my-project", cancellation);
WorkspaceInfo workspace = await connection.CreateWorkspace(project.Path, cancellation);
await connection.ConfigureWorkspace(workspace.Id, AiService.ClaudeCode, AiModel.Opus, AiEffort.High, cancellation);

WorkspaceGroup group = await connection.CreateGroup("Clients", null, cancellation);
WorkspaceGroup nested = await connection.CreateGroup("Acme", group.Id, cancellation);
await connection.MoveWorkspace(workspace.Id, nested.Id, cancellation);

connection.EventReceived += remoteEvent =>
{
    if (remoteEvent.Kind == RemoteEventKind.MessageAdded)
    {
        Console.WriteLine($"{remoteEvent.Message?.Role}: {remoteEvent.Message?.Text}");
    }
};

await connection.Prompt(workspace.Id, "Create a hello world program", cancellation);
await connection.Prompt(workspace.Id, "Make it print in French", cancellation);
ChatHistory newest = await connection.GetHistory(workspace.Id, null, 30, cancellation);
ChatHistory older = await connection.GetHistory(workspace.Id, newest.Start, 30, cancellation);
await connection.WatchFiles(workspace.Id, [string.Empty], cancellation);
WorkspaceFiles files = await connection.ListFiles(workspace.Id, string.Empty, cancellation);
```

The workspace is named `my-project` after its folder, and the first prompt starts an AI session attached to it. The groups only organize workspaces in Auto Remote and create nothing on disk. `Prompt` returns at once; the conversation arrives as events as the AI writes it, and a prompt sent while the AI is working joins that work. History is read in chunks, newest first. After `WatchFiles`, `FilesChanged` events report changes to those folders (each call replaces the folders watched before). A refusal such as an unknown folder throws `RemoteException`.

## Use the client app

The Android app (`Client/Mobile/`) and the desktop app (`Client/Desktop/`, a window without a title bar of its own that opens maximized and runs on Windows and Linux) are the same client and use the same port as the web client; the desktop app keeps its settings in the user's application data unless started with `--data-folder <path>`. Everything below applies to both.

1. On first launch, enter the server's host, port and access key. They are saved on the device, the client accepts whatever certificate the server presents, and later launches reconnect straight to the workspaces. If the connection is lost, for example while the app was in the background, the client reconnects by itself, shows "(reconnecting…)" after the workspace name meanwhile and then reads what it missed, so messages posted in the meantime appear. Everything else, the workspaces, groups, settings and conversations, lives on the server.
2. The menu button opens the drawer listing workspaces and groups as a tree. The client always opens with no workspace focused and the drawer open. A filter box at the top narrows the list as you type: a workspace shows when its name or folder contains the text (ignoring case), together with the groups holding it, and a group whose name matches shows with everything in it; groups are all open while a filter is set, and the filter only changes what is shown. Tap a workspace to focus it, tap a group to collapse or expand it. Both are listed in a custom order that is the same on every client; up and down buttons (triangles) move a group or workspace one place among its siblings, and new ones go to the end. A group has buttons to add a group inside it (+), rename it (pencil), move it (arrow) and delete it (cross); a workspace has a move button. Moving asks for the group to put it in, or the top level; a group cannot go into itself or anything inside it. Deleting a group keeps what is in it and moves that up a level. New workspace, Clone workspace, New group and Change server are at the bottom.
3. A new workspace is a folder on the server: browse from the server's default folder, create folders as needed, then start the workspace in the folder you are viewing. The workspace takes the folder's name. Cloning is the same screen with a repository URL and an optional folder name added: the server clones the repository into a new folder inside the folder you pick and starts a workspace in it. Groups in the drawer are different: they only organize workspaces in Auto Remote and are not created on the server's disk.
4. A focused workspace has a gear at the top right that opens its settings (press it again to go back). The mobile client shows chat, files and scripts as tabs along the bottom, plus a History tab when the workspace is a git repository; the desktop and web clients have no bottom tabs and show the file system, the content of the selected file and the chat as three panels side by side with draggable separators between them (a thin line, with a wider invisible grip), the file system much narrower (a seventh of the width) and the other two equal at first. The chat panel has its own tabs, as in Auto Dev: an underlined tab for the one showing, Chat, Script and History (when the workspace is a git repository) in the desktop and web clients. The message box has no background or border, only the send button beside it. On the desktop and web clients it starts taller, its height can be dragged to anything by its top edge (even shorter than the text), and typing grows it just enough to show the text when it is too short (leaving space for the conversation); once it is empty again, for example after sending, it returns to the height it had before it grew. Files and images are attached by pasting them (Ctrl+V; a copied image or copied files) or with the paperclip button beside the box; they show as removable chips above the box and are sent with the next message (up to 2 MB each), which tells the AI where to read them. In the conversation a sent message shows its text with the attached files as named chips below it (hover for the server path), not as raw `Attached file:` lines; the clients recognize those trailing lines in the stored prompt, so older history displays the same way. What is typed in a workspace's message box is kept on the device per workspace (in a file beside the saved connection settings in the Avalonia clients, in the browser's local storage in the web client), so unsent text comes back after the app or tab was closed, and it is cleared once sent. When a prompt sent from a client's own chat makes a workspace work, that client shows a notification saying "<workspace> is ready" once the workspace is ready again (work started from another client or a script does not trigger it, nor does a prompt that could not be sent). Each workspace has its own notification, and opening it brings that workspace to the front (on mobile also when the app has to start first, in which case the workspace opens as soon as the app is connected; in the browser clicking the notification focuses the page and the workspace). It is an Android notification on mobile, a Windows toast or a `notify-send` notification on the desktop client (nothing when `notify-send` is missing), and a browser notification in the web client, which asks for permission the first time you send a prompt and only works while the page is open. Android stops apps in the background, so while mobile work runs the app is kept connected by a foreground service whose ongoing notification names the workspaces working; it ends when they are ready again, and after twelve hours at the latest. Android may ask once to allow notifications. Text in the chat, the file preview and the script output can be selected with a mouse, by double tapping, or on a touch screen by holding a finger still on a word (which selects it, and dragging then extends the selection); a touch that moves first is a scroll and never selects, so touching text to scroll does not highlight it. Chat is a live conversation: the AI's messages appear as it writes them, rendered as markdown (your own messages stay plain text), you can keep sending messages while it works and they join that work, and the newest messages load first with older ones loading as you scroll to the top. Files shows the workspace folder as a tree like the Auto Dev app, names only: tap a folder to open or close it in place (a button closes every folder) and tap a file to preview it. On mobile, double-tap a folder to make it the root of the tree; the desktop and web trees always start at the workspace folder. None shows the root path or an up button. The desktop and web trees keep the file being previewed selected with the folders above it opened, and offer Copy Name, Copy Relative Path and Copy Absolute Path when a file or folder is right clicked (a right click never opens or closes a folder). A `.filehide` file, in the workspace folder or any folder inside it, hides files and folders from the tree. It uses the `.gitignore` format (comments, `!` to show again, a trailing `/` for folders only, `*`, `?`, `[...]`, `**`, and patterns with a `/` anchored to the file's folder), applies to its folder and everything below, and hides everything inside a hidden folder. A magnifier button at the top of the file system swaps the tree for a search, as in Auto Dev: type to find files by name (fuzzy, best match first, at most 50), or tick Search file contents to list the lines of text files that contain the text (at most 200, ignoring case) with their file and line number. Searches skip `.git` and what `.filehide` hides (unless See hidden files is on). Choosing a hit closes the search and previews the file; a line hit also opens the find bar with the text and moves to that line. The eye button next to Collapse All turns See hidden files on to show them again; it is off by default. The tree updates by itself when an open folder changes, for example while the AI edits files. A previewed file has a bar on top like Auto Dev's editor: a label saying whether it is a file or a diff, its path, a find button, a word wrap button (not for rendered markdown) and a button that closes it. The text sits straight on the panel background. A markdown file (`.md`, `.markdown`) is shown rendered; other files are shown as monospaced text with line numbers (long lines scroll sideways, or wrap with the word wrap button and keep one number per line), colored by syntax when the language is recognized (for example C#, JSON, YAML, XML and project files, JavaScript, TypeScript, Python, shell, SQL, CSS, HTML, INI, `.env`, CSV and Dockerfiles). Every previewed file, rendered markdown included, has a find bar (the magnifier button or Ctrl+F) with a match count, match case and whole word options, and next and previous match (Enter and Shift+Enter) that marks the matches in the text; in rendered markdown it searches the text as shown (formatting characters are not part of it) and a line hit from file search only opens the bar. On the desktop and web clients the message box grows with its lines of text, centered vertically in the box, until it fills it. The file system's buttons sit at the right of its header. Settings holds the AI service, model and effort (Claude Code with Sonnet on high by default), and Rename and Delete. Rename renames the workspace's folder on the server. Delete removes the workspace, and by default its folder and everything in it; untick the box to keep the folder.
5. A workspace whose folder is a git repository shows its git state, and every git action runs on the server. At the top of the file system sits the version section: the branch (or the tag or a note when the head is not on a branch), a tag at the head, the head commit's message and abbreviated hash, and an asterisk with a highlighted background while there are uncommitted changes; like in Auto Dev it is plain until hovered, with a line under it. The questions it asks (a commit message, a branch name, the remote URL and so on) open with their box focused and ready to type; Escape cancels and Enter submits (Enter does not answer a question that destroys work, such as a reset, which only its button does), and on a touch keyboard the text starts with a capital letter, except for a URL or an email. Tapping it offers Commit (stages everything, asks for a message and pushes the branch when there is a remote), Reset (discards every uncommitted change after a confirmation), Branch (creates a branch at the head, checks it out and pushes it), Tag (annotated, pushed) and Remote. The first time a commit, tag or history rewrite needs it and git does not know who you are, the client asks for a name and email and saves them in the server user's global git configuration. The files in the tree are colored like Auto Dev: new files green, changed files and the folders containing changes yellow, ignored files and folders dim. The changes button next to Collapse All switches the tree to Changes Mode, a tree of only the changed files (deleted ones in red); tapping a file there shows its diff in the content panel, the whole file with added and removed lines marked and the line numbers before and after. The History tab draws the commits of every branch newest first the way the Git Graph extension of VS Code does: a graph on the left with a colored line for each branch that is open and a dot per commit, curves where branches split and merge, the branch and tag badges in the color of their line next to the subject (a local branch and its remote copy on the same commit share one badge), and the author, date with time and abbreviated hash on the right of each one line row, with the full hash as its tooltip; tapping a commit lists the files it changed as a tree, with the graph carrying on beside it, and tapping one of those shows its diff in the content panel. Older commits load on request, and a Fetch button next to Refresh fetches the remote. Right clicking a commit offers Checkout (a plain commit, which detaches the head), and right clicking a branch or tag badge opens its menu: Checkout (changes that are not committed are discarded after a confirmation that says so), Squash, Rebase and Merge between the badge's branch and the checked out branch in either direction, and Delete (locally and on the remote, after a confirmation). Squash and a rebase or merge of a branch with several commits ask for the message of the one commit that replaces them, defaulting to the tip's message; rebase and merge need a clean working tree and tell you when there is nothing to do. A rebase or merge that conflicts is handed to the workspace's AI: nothing blocks the screen: a workspace is Ready (nothing runs), Working (the AI runs), Running (a script runs) or Managing (git runs), and it only leaves Ready for one of them, so git actions, scripts, rename and delete wait until it is Ready again, and more AI input is only taken while Ready or Working. While the work in a workspace runs (the AI, a script or git), the message box's send button is replaced by a Stop button, which ends the work at once and keeps what it did, and a Cancel button, which ends it and reverts what it did (the AI's or a script's file changes are put back, which needs a git repository, and git actions are undone), each asking "are you sure" first; the workspace is Stopping or Canceling meanwhile, locked like any other busy state. While the AI works and something is typed the send button comes back, so more input can still be given. While git is working on the server (from any client) the workspace shows it like it does while the AI works (the top bar turns blue), the message box is locked from sending with a hint saying git is working, and a bar above the message box offers Cancel and undo; the chat shows what the AI was asked and does, and when it cannot resolve the conflicts everything is put back and you are told. A merge fast-forwards the target, pushes it and deletes the merged branch everywhere. While a workspace is focused its checked out branch is fetched and pulled every minute and whenever the history opens (changes that are not committed are stashed and restored around the pull, with the AI resolving conflicts of the restore). Everything refreshes by itself when files change and when the AI finishes working. Commit, Reset and Branch are refused while the AI is working in the workspace. The popup that asks for a commit message, branch name or a confirmation closes as soon as it is submitted while the action runs (the workspace shows git as working); if the action fails, the popup returns with what was typed and the error.
6. A git remote icon sits at the top right of a focused workspace, left of the usage icon: it sets the `origin` remote of the workspace, turning a folder that is not a repository into one first, or repoints the remote of an existing repository (the field starts with the current URL).
7. While the AI is working or a script is running in the focused workspace, the header bar with the workspace title turns blue, on every tab and in every layout.
8. Next to the gear is a usage icon, colored by how fast the session limit of the workspace's AI service is being used: green when well under an even pace, blue when under, the normal color when even, orange when over and red when well over or used up. Tapping it opens the session and week usage with their reset times. The server reads Claude Code's limits from its `/usage` report and Codex's from the newest Codex session recorded under `~/.codex` (so they are as fresh as the last Codex run, and a window that already reset shows 0%), reuses a result for a minute, and clients ask once a minute.
9. Only the desktop client has a window without a title bar: the header is the title bar (drag it, double click to maximize) and minimize, maximize and close buttons sit to the right of the gear. Its file system also has buttons that open the workspace folder in the file manager (when the folder exists on the machine the client runs on, which is the case when the server runs there too) and copy the workspace folder's path.
10. Every client runs `.cs` single-file scripts and `.task` files on the server. They show with a play icon in the file system and run when double clicked (double tapped on mobile); the Script tab, between Chat and History on the desktop and web clients and between Files and History along the bottom on mobile, opens. Its dropdown lists the runs (running ones with a dot; a finished one can be removed), a task shows one sub tab per script, and the output of the chosen script appears live in a monospaced view with its state, a button that copies all of it and, while running, a Stop button (a whole task stops) and a box that sends a line to the script's input. Only one script or task runs in a workspace at a time, a script cannot start while the AI is working or git is running, and the AI cannot get a prompt while a script runs (the message box is disabled, and the server refuses it from any client). The server keeps the runs, so they are still there after the client reconnects.
11. The chat and the script output each have an auto scroll toggle (a double arrow button: at the bottom right of the chat, and in the script's header beside Copy). Both start on, and while one is on its log jumps to the bottom whenever new content arrives; turn it off to read earlier output while more arrives. The two are independent and are not remembered between sessions.

## Use the web client

`Client/Web/index.html` is a single static file with the same screens and behavior as the client apps: serve it from any static host such as GitHub Pages (or open it from disk) and enter the server's host, port and access key. It always connects with `wss`. The settings are saved in the browser. With a self-signed server certificate, open `https://host:port` in a tab once and accept the certificate; the connect screen links there. In a desktop browser Enter sends a message and Shift+Enter adds a line.
